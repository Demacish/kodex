# 0007. The backend owns authentication

Status: Accepted (implemented in phase 3); extended by [0020](0020-passkeys-and-two-step-login.md)

## Context

v1 logs in through NextAuth in the Next.js frontend and requires an external
OIDC provider with specific groups.

## Decision

- **Local accounts** with argon2id passwords (argon2-cffi). A server
  without users lets the first visitor create the admin; after that, admins
  add users. `python -m kodex.core.auth.cli set-password` sets a password
  from the command line (v1's users have none) and is the way back in for a
  locked-out admin.
- **Web sessions:** a random token in an HttpOnly, SameSite=Lax cookie,
  stored as a SHA-256 hash, valid for `SESSION_DAYS` and extended while in
  use. CSRF: double submit, the session's token in a readable cookie that
  the client echoes in `X-CSRF-Token` on unsafe requests. Changing a
  password ends the user's other sessions; disabling a user ends all of
  them.
- **Throttling:** a username, or an address, with too many failed logins in
  `LOGIN_LOCKOUT_MINUTES` waits (429 with `Retry-After`).
- **OpenID Connect** is optional: Authorization Code with PKCE (S256), a
  confidential or public client. It is written with httpx and joserfc
  instead of Authlib: discovery, the code exchange and ID token checks
  (signature against the provider's keys, issuer, audience, expiry, nonce)
  are a little code, and joserfc already verifies v1's bearer tokens. The
  state, nonce and verifier wait server-side for ten minutes and are used
  once. Users are matched by subject, so v1's users keep their accounts; a
  required group limits who may log in, and an admin group, when set,
  decides who is an admin.
- **Apps** send a bearer token: a personal API key, or the provider's
  access token as in v1.
- **Personal API keys** (`kdx_` and 43 random characters, shown once, only
  hashes kept), each for one purpose: `app` (bearer), `opds` (the HTTP
  Basic password), `kosync` (KOReader sends the key's MD5, which is kept
  too; the key is random, so that is no weaker) and `kobo`. v1's per-user
  OPDS token keeps working for OPDS and KOSync until it is revoked.
- **Roles:** `admin`, `user`, and `guest`, who can read but not make
  requests. `users.is_admin`, which v1's routes check, follows the role.

## Consequences

Kodex works without an identity provider; roles live in Kodex. Moving a v1
server means adding the new redirect URI at the provider (or setting
passwords from the command line) before the Next.js frontend goes.
